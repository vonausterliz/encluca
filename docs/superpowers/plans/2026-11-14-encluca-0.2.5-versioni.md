# encluca 0.2.5 — Versioni precedenti dei file: piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** quando un file viene sovrascritto, l'hub conserva la versione precedente (cifrata); dalla pagina del NAS si può riportare tutto com'era a una certa data/ora o ripristinare una versione di un singolo file.

**Architecture:** tutto sull'hub, nessuna modifica al protocollo né ai client. Le versioni stanno in `<dati>/versions/` con un indice `versions.json`, sul modello del cestino (`trash.go`). Ogni voce dell'indice dei file ricorda quando è diventata la versione corrente (`Entry.At`), così "com'era il giorno X" si calcola senza conoscere i nomi in chiaro. Un ripristino crea una nuova revisione: arriva ai PC come una modifica normale ed è a sua volta annullabile.

**Tech Stack:** Go 1.27.4 (solo libreria standard), HTML/JS senza framework in `web/hub.html`.

**Spec:** `docs/superpowers/specs/2026-11-13-encluca-0.2-design.md` §3.

## Global Constraints

- Build/test: `export GOTOOLCHAIN=go1.27.4; go test -timeout 900s ./...`. Ogni `T("…")` nuovo va in `enMessages` (`i18n.go`) nello stesso commit; ogni testo nuovo in `web/hub.html` va nel dizionario `EN` della pagina.
- Nessuna dipendenza nuova. Nessuna modifica a `client.go` né al protocollo (`protoVersion` resta 2).
- Valori dalla spec: **5 versioni per file** (predefinito), **0 = disattivato**, **età massima 90 giorni** (predefinita). Le versioni **non** entrano nel backup su Drive.
- I file delle versioni restano cifrati; l'hub non conosce nomi né contenuti.
- Le cartelle vuote (`Entry.Dir`) non hanno versioni.
- Commit in italiano con la riga `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`; il controllo dei segreti (`.githooks`) resta attivo.

## Review Focus

1. **Interruzione a metà di una sovrascrittura.** Se l'hub si ferma tra il salvataggio della versione e la scrittura del file nuovo, il file corrente non deve mai mancare dalla cassaforte. → `TestVersionSaveNeverRemovesCurrent` (Task 1).
2. **Ripristino annullabile.** Dopo "riporta com'era a X", un secondo "riporta com'era a un istante prima del ripristino" deve rimettere i contenuti di prima. → `TestRestoreAtIsReversible` (Task 2).
3. **File modificato dopo X e poi eliminato.** "Riporta com'era a X" deve restituire il contenuto che aveva a X, non quello al momento dell'eliminazione. → `TestRestoreAtModifiedThenDeleted` (Task 2).
4. **File di prima dell'aggiornamento.** Le voci senza data (`At == 0`, caricate con una versione precedente dell'hub) non vanno toccate da "riporta com'era" finché non vengono modificate. → `TestRestoreAtIgnoresUndatedEntries` (Task 2).
5. **Cambio del numero di versioni.** Passando da 5 a 2 le versioni in eccesso vengono eliminate; con 0 una sovrascrittura non conserva nulla ma le versioni esistenti restano ripristinabili finché non scadono. → `TestVersionsKeepSetting` (Task 1).

### Task 1: Conservare le versioni precedenti

**Files:**
- Create: `versions.go`, `versions_test.go`
- Modify: `hub.go` (`Entry`, `hubConfig`, `Hub`, `newHub`, `apiFile` PUT, `putDir`, `adminStatus`), `trash.go` (`restoreTrashLocked` imposta `At`), `i18n.go`

**Interfaces:**
- Produces:
  - `Entry.At int64 \`json:"at,omitempty"\`` — istante (unix nano, orologio dell'hub) in cui questa revisione è diventata corrente; 0 = sconosciuto. Va impostato in ogni punto che crea o aggiorna una voce (`apiFile` PUT e DELETE, `putDir`, `restoreTrashLocked`).
  - `type versionItem struct { Path string \`json:"p"\`; File string \`json:"file"\`; Size int64 \`json:"size"\`; SHA string \`json:"sha"\`; MTime int64 \`json:"mtime"\`; Rev int64 \`json:"rev"\`; Since int64 \`json:"since"\`; Replaced int64 \`json:"replaced"\`; Dev string \`json:"dev,omitempty"\` }` — `Since` = `Entry.At` della revisione, `Replaced` = quando è stata sostituita.
  - `type VersionsConfig struct { Keep int \`json:"keep"\`; MaxAgeDays int \`json:"maxAgeDays"\` }`; `hubConfig.Versions *VersionsConfig \`json:"versions,omitempty"\`` (nil = predefiniti); `func (h *Hub) versionsCfgLocked() VersionsConfig` → `{5, 90}` se nil.
  - `Hub.versions []versionItem`; `func (h *Hub) versionsDir() string` (`<dati>/versions`); `func (h *Hub) loadVersions()`; `func (h *Hub) saveVersionsLocked()`.
  - `func (h *Hub) keepVersionLocked(full string, cur *Entry, now int64, force bool) error` — conserva il file corrente di `cur` come versione. Con `force == false` non fa nulla se `Keep == 0`.
  - `func (h *Hub) pruneVersionsLocked()` — toglie le versioni oltre `Keep` per percorso (le più vecchie per `Replaced`) e quelle con `Replaced` più vecchio di `MaxAgeDays` (0 = nessun limite di età).
  - `func (h *Hub) versionsStatsLocked() map[string]any` → `{"files": n, "bytes": totale, "keep": Keep, "maxAgeDays": MaxAgeDays}`; `adminStatus` lo espone come `"versions"`.

### Task 2: Ripristino (a una data, o di una singola versione)

**Files:**
- Modify: `versions.go`, `versions_test.go`, `trash.go` (estrae la scelta dei candidati), `hub.go` (`handler`), `i18n.go`

**Interfaces:**
- Consumes: tutto il Task 1.
- Produces:
  - `func (h *Hub) restoreVersionLocked(i int, now int64) error` — rimette nella cassaforte la versione `h.versions[i]`: se la voce corrente è un file vivo la conserva come versione (`force == true`, così il ripristino è sempre annullabile); se è una cartella vuota la toglie; sposta il file della versione al suo posto; nuova voce con `Rev+1`, `At = now`, `Dev = "versions"`; toglie la versione dall'indice.
  - `func (h *Hub) versionAtLocked(path string, at int64) int` — indice della versione di `path` valida all'istante `at`: tra quelle con `Replaced > at`, quella con `Replaced` minore, purché `Since <= at` (`Since == 0` vale come "da sempre"); `-1` se non c'è.
  - `func (h *Hub) restoreAtLocked(at int64, dry bool) (changed, undeleted int)` — riporta la cassaforte a com'era all'istante `at`. Con `dry == true` conta soltanto.
  - `func (h *Hub) trashCandidatesLocked(since int64) []int` — gli elementi del cestino che `restoreTrashLocked(since)` ripristinerebbe (usata anche da `restoreAtLocked` per il conteggio).
  - API amministratore:
    - `POST /admin/api/versions/config` `{"Keep": n, "MaxAgeDays": n}` (`withAdmin`) — `Keep` da 0 a 100, `MaxAgeDays` da 0 a 3650; fuori da questi limiti → 400. Salva e chiama `pruneVersionsLocked()`.
    - `POST /admin/api/versions/restore-at` `{"At": "<RFC3339>", "DryRun": bool}` (`withAdmin`) → `{"changed": n, "undeleted": m}`. `At` nel futuro o non valido → 400.
    - `GET /admin/api/vault/versions?p=<enc>` (`withBrowse`) → elenco `[{"id": File, "size": dimensione in chiaro, "mtime": MTime, "since": Since, "replaced": Replaced}]`, dalla più recente.
    - `POST /admin/api/vault/versions/restore` `{"P": enc, "ID": File}` (`withBrowse`) → `{"ok": true}`; versione inesistente → 404.

- [ ] **Step 1: test che falliscono** in `versions_test.go`. Un helper `put(env, tok, p, base, contenuto)` e `content(env, p)` (legge il file corrente dal disco dell'hub). Per separare gli istanti, dopo ogni PUT si legge `now := time.Now().UnixNano()` e si aspetta 2 ms:
  - `TestRestoreSingleVersion`: PUT `"uno"`, PUT `"due"`; `restoreVersionLocked(0, now)` → il file corrente è `"uno"`, la voce ha `Rev == 3` e `Dev == "versions"`; in `versions` c'è una sola voce, con contenuto `"due"`.
  - `TestRestoreAt`: file A: `"a1"`, poi istante X, poi `"a2"`, poi `"a3"`. File B: `"b1"` prima di X, mai modificato. `restoreAtLocked(X, true)` → `(1, 0)` e nulla cambia; `restoreAtLocked(X, false)` → `(1, 0)`, A contiene `"a1"`, B è intatto e la sua `Rev` non cambia.
  - `TestRestoreAtIsReversible`: come sopra; si prende l'istante Y subito prima di `restoreAtLocked(X, false)`; poi `restoreAtLocked(Y, false)` → A contiene di nuovo `"a3"`.
  - `TestRestoreAtModifiedThenDeleted`: `"a1"`, istante X, `"a2"`, DELETE → `restoreAtLocked(X, false)` restituisce `undeleted == 1` e il file corrente contiene `"a1"`.
  - `TestRestoreAtDeletedOnly`: `"a1"`, istante X, DELETE → dopo il ripristino il file contiene `"a1"`.
  - `TestRestoreAtIgnoresUndatedEntries`: una voce con `At` azzerato a mano (come dopo un aggiornamento) e nessuna versione → `restoreAtLocked` di qualunque istante passato restituisce `(0, 0)` e non la tocca.
  - `TestRestoreAtKeepsFilesCreatedLater`: un file creato dopo X resta dov'è.
  - `TestVersionsAdminAPI` (sessione amministratore come in `TestHubTrashRestore` di `security_test.go`): `versions/config` con `Keep: 2` → 200 e `versionsCfgLocked().Keep == 2`; con `Keep: 500` → 400. `versions/restore-at` con `DryRun: true` → conteggi giusti; con una data futura → 400. `vault/versions` e `vault/versions/restore` rispondono 403 con l'esplorazione disattivata e funzionano con l'esplorazione attiva (`cfg.BrowseEnabled = true`); `restore` con `ID` inesistente → 404.
- [ ] **Step 2:** `go test -run 'TestRestoreSingleVersion|TestRestoreAt|TestVersionsAdminAPI' .` → FAIL.
- [ ] **Step 3: implementa.** `restoreAtLocked`: (1) con `dry == false` esegue `restoreTrashLocked(at)` e ne conta i ripristinati come `undeleted`; con `dry == true` conta `len(trashCandidatesLocked(at))`. (2) Per ogni voce file viva con `At > at`: `i := versionAtLocked(path, at)`; se `i >= 0` conta `changed` e, se non è `dry`, chiama `restoreVersionLocked`. Le voci con `At == 0` si saltano (Review Focus 4). Un percorso tornato dal cestino al passo 1 ha `At = now`, quindi il passo 2 lo riporta al contenuto di X se era stato modificato prima di essere eliminato (Review Focus 3). In `dry` i due conteggi possono riferirsi allo stesso file: va bene, sono mostrati separati. Alla fine, se qualcosa è cambiato: `saveIndex`, `saveVersionsLocked`, `broadcast`, e una riga nel registro `T("Ripristino a %s: %d file riportati alla versione precedente, %d file eliminati recuperati")`.
