# Chiusura automatica e controllo dei file in uso — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** la cassaforte aperta si chiude da sola dopo N minuti senza modifiche ai file, con avviso 2 minuti prima e pulsante "Rimanda". Né la chiusura automatica né quella manuale partono se un file della cartella è aperto in un programma: quella manuale mostra un popup con l'elenco dei file da chiudere.

**Architecture:** tutto nel servizio client.
- `scanLoop` (ogni 2 s) registra l'ultima attività quando la scansione trova una modifica locale, poi chiama `autoCloseTick(now)`, che decide se chiudere usando la `Close()` sicura di oggi.
- `Close()` per prima cosa chiama `filesInUse(work)` (un'implementazione per sistema operativo, più i file di blocco dei programmi). Se trova file aperti restituisce `*inUseError` senza toccare nulla.
- L'API locale traduce `*inUseError` in 409 con l'elenco. L'interfaccia mostra il popup e la CLI stampa l'elenco.

**Tech Stack:** Go (libreria standard + `golang.org/x/sys/windows`, già tra le dipendenze), HTML/JS in `web/client.html`.

**Spec:** `docs/superpowers/specs/2026-11-13-encluca-0.2-design.md` §6 (Chiusura automatica). Estensione decisa dall'utente il 2026-11-22: controllo dei file in uso per la chiusura automatica **e manuale**. La manuale si blocca con un popup e l'utente chiude i file prima di riprovare. **Nessun "chiudi comunque".**

## Fuori da questo piano (deciso)

- **Chiusura al blocco schermo / sospensione:** spetta al processo dell'icona (§7) nel suo piano, che chiamerà `POST /api/close`.
- **Notifica desktop** "si chiude tra 2 minuti": arriva con avvisi e icona (§5, §7). Qui l'avviso è solo nell'interfaccia web.
- **Cassaforte "rimasta aperta" dopo un riavvio** (`staleOpen`): senza password non si può cifrare, quindi la chiusura automatica non la tocca.
- **Editor che leggono il file e lo chiudono subito** (gedit, VS Code, Blocco note): non sono rilevabili. Per loro valgono l'avviso dei 2 minuti e il Rimanda.

## Global Constraints

- Chiusura automatica: predefinito **30 minuti**, **0 = mai**, ammessi 0–1440. Un `config.json` senza il campo vale 30.
- Avviso **2 minuti** prima.
- Riprova dopo un blocco: **1 minuto** se il motivo sono file in uso, **5 minuti** per gli altri motivi.
- Inattività = nessuna modifica locale trovata dalla scansione. I file arrivati dal NAS non contano.
- La chiusura automatica usa **la stessa `Close()`**, senza un nuovo percorso di cancellazione.
- Anti-obiettivo: **non deve mai cancellare modifiche non ancora cifrate**.
- Il controllo dei file in uso blocca sia la chiusura manuale (UI, CLI, futura icona) sia quella automatica. Non esiste un modo per forzarlo.
- Se il controllo non riesce (per esempio `lsof` manca) non blocca la chiusura: scrive una riga nel registro e procede come oggi.
- Ogni `T("…")` nuova ha la sua voce in `enMessages` (`TestTranslationsComplete`). Ogni testo nuovo della UI ha la sua voce in `EN` di `web/client.html`.
- Build senza cgo: `CGO_ENABLED=0`, `GOTOOLCHAIN=go1.27.4`. `GOOS=windows` e `GOOS=darwin` devono compilare.

## Review Focus

1. **File di blocco rimasti da un crash** (`.~lock.x.odt#` senza LibreOffice aperto) bloccherebbero la chiusura per sempre. Nel popup la voce dice che è un file di blocco e cosa fare: se il programma è chiuso, il file di blocco è rimasto da un'interruzione e va eliminato. Il popup offre anche il pulsante "Apri cartella". → `TestInUseLockFile` (Task 2) controlla `Lock: true` e il nome del documento.
2. **Indicizzatori e antivirus** che aprono i file per un attimo (tracker-miner, tracker-extract, mdworker, mds_stores, Spotlight) non devono bloccare. → `TestInUseIgnoresIndexers` (Task 2) sulla funzione di filtro per nome del processo.
3. **Chiusura bloccata** (file in uso, nome lungo, cancellazioni di massa): niente chiusura, motivo visibile, nuovo tentativo dopo il ritardo giusto, poi la chiusura riesce appena il motivo sparisce. → `TestAutoCloseBlockedRetries` (Task 1), `TestAutoCloseInUseRetries` (Task 2)
4. **Il processo encluca stesso** (scansione, cifratura) non deve risultare "in uso". → `TestInUseIgnoresSelf` (Task 2)
5. **Riapertura dopo una chiusura automatica**: il conteggio riparte da zero. → `TestAutoCloseReopenResets` (Task 1)

- Create: `inuse_test.go`

- Modify: `autoclose.go` (`autoCloseRetryFor`), `main.go` (helper `post`: 409 per `*inUseError`), `cli.go` (`case "close"`: stampa l'elenco), `i18n.go`

**Interfaces:**
- Consumes: `autoCloseTick`, `autoCloseRetryFor` (Task 1)
- Produces:
  - `type inUseFile struct { Path string "json:\"path\""; Proc string "json:\"proc,omitempty\""; Lock bool "json:\"lock,omitempty\"" }`. `Path` è relativo alla cartella aperta con `/` come separatore. `Proc` è il nome del programma se il sistema lo dice. `Lock` è true se rilevato da un file di blocco.
  - `type inUseError struct{ Files []inUseFile }`, con `Error()` = `T("non chiudo: %d file sono aperti in un programma (%s). Chiudili e riprova")` (al massimo 3 nomi, come in `Close`)
  - `func filesInUse(work string) ([]inUseFile, error)`: unisce `openByProcesses(work)` (per sistema) e `lockFiles(work)`, senza duplicati per `Path`, ordinato
  - `func openByProcesses(work string) ([]inUseFile, error)`, una per file `inuse_*.go`
  - `func lockFiles(work string) []inUseFile`: `.~lock.NOME#` → `NOME` (LibreOffice), `~$…` → voce col nome del file di blocco (Word tronca il nome, quindi non si ricostruisce), `.NOME.swp` → `NOME` (vim). Tutte con `Lock: true`.
  - `func ignoredProc(name string) bool`: true per `tracker-miner-fs-3`, `tracker-extract-3`, `localsearch-3`, `localsearch-extractor-3`, `baloo_file`, `baloo_file_extractor`, `mdworker`, `mdworker_shared`, `mds`, `mds_stores`, `encluca`, `nautilus`

- [ ] **Step 3: implementa**

- **`inuse_linux.go`:** percorre `/proc/[0-9]*/fd/*`, salta `os.Getpid()` e i processi non leggibili (altri utenti) senza errore. `os.Readlink` di ogni fd: tiene i link sotto `work + "/"`, solo file regolari. `Proc` da `/proc/PID/comm` (senza `\n`). Scarta `ignoredProc`.
- **`inuse_darwin.go`:** esegue `lsof -n -F pcn +D <work>` con timeout di 10 s. Righe `p` = PID, `c` = comando, `n` = percorso. Salta il proprio PID e `ignoredProc`. Uscita 1 senza output = nessun file aperto, non è un errore.
- **`inuse_windows.go`:** per ogni file regolare sotto `work`, `windows.CreateFile(path, GENERIC_READ, 0 /* nessuna condivisione */, nil, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, 0)`. Se l'errore è `ERROR_SHARING_VIOLATION` il file è in uso (`Proc` vuoto), altrimenti si chiude l'handle.
- **`Close()`:** subito dopo il controllo `c.cip == nil`, **prima** di impostare `busy`, legge `work` sotto lock, rilascia il lock e chiama `filesInUse`. Se ci sono voci restituisce `&inUseError{…}`. Se `filesInUse` dà errore, scrive `T("controllo dei file aperti non riuscito: %v")` nel registro e prosegue.
- **`autoCloseRetryFor`:** 1 minuto se `errors.As(err, *inUseError)`.
- **`post` in `main.go`:** con `*inUseError` risponde `409` e `{"error": msg, "inUse": files}`.
- **CLI `close`:** stampa una riga per file (`  percorso — programma`) sotto il messaggio, uscita con codice di errore come oggi.
